# Codebase Structure

A Rust workspace (`crates/`), operator scripts for the machines Motor runs on
(`script/`), repository gates (`scripts/`), and public documentation
(`docs/`). This file is a map; to find a specific symbol or file, search the
code rather than this document. `ARCHITECTURE.md` explains how the parts fit
together.

## Top level

```text
crates/
  motor-module/          ck-motor, the client module (CortexKit daemon module and `ck motor` CLI)
  motor-protocol/        exec-remote/v1 frames and codec shared by client and runner
  motor-lease/           lease tokens and signatures; contracts/cloud/ is the byte-pinned broker contract
  motor-runner/          the runner daemon: admission, queue, workspaces, sandbox, VM backends
  motor-host/            hosted server agent: TLS admission, relay to the tenant VM, broker reporting
  motor-vm-helper/       root service owning Firecracker tenant VMs (and an unused per-job slot pool)
  motor-vm-loader/       userfaultfd snapshot loader for per-job VMs (unused)
  motor-vm-guest/        one-command guest supervisor for per-job VMs (unused)
  motor-macvm/           macOS VM driver for the macOS backend (Virtualization.framework)
  motor-macagent/        guest agent inside each macOS job VM
  motor-winagent/        guest agent inside each Windows job VM; outside the workspace, own Cargo.lock
  prefrontal-build-slot/ compiler wrapper limiting concurrent compiles; vendored, see its VENDORED.md
script/
  runner/                Linux runner setup, deploy, the toolchain manifest (toolchain.json) and its checks
  hosted-host/           hosted server installer and admin client (hosted_host.py)
  tenant-image/          builds the tenant VM kernel and root filesystem
  tenant-provision/      creates, resizes and removes tenant VMs (provision.py)
  windows-runner/        Windows runner host on Hyper-V: release bundle, install, qualification
  windows-vm/            Windows job VM baseline for the QEMU backend: build and qualification
  macos-runner/          macOS runner install and job VM image
  boat-image/            overflow sandbox image and its host services
  boat-probe/, cache-bench/, hyperv-spike/, tenant-vm-spike/
                         probes and experiments, run by hand
scripts/                 gate.sh, mixed-version.py, safety fences, card build, script tests
docs/                    public documentation, one topic per file
test-vectors/exec-remote-v1/
                         protocol corpus, generated by crates/motor-protocol/tests/generate_vectors.py
```

## `crates/motor-runner/src`

- `main.rs`: command-line flags, backend choice (`--backend`), tenant VM and
  overflow-sandbox modes.
- `engine.rs`, `engine/`: job admission, queue, dispatch and lifecycle.
- `server.rs`: the protocol server for client frames.
- `storage.rs`: the job table and retention.
- `workspace.rs`, `workspace/`: Git mirrors, checkouts at the caller's path,
  dependency preparation, warm builds.
- `isolation.rs`, `isolation/`, `systemd.rs`, `network*.rs`, `permissions/`:
  the Linux job sandbox.
- `cpu.rs`, `disk.rs`: vCPU claims and pinning; disk admission and cleanup.
- `compile_cache.rs`, `writer.rs`, `writer/`, `remote_cache*`: the shared
  compile cache, its fills and the remote cache gateway.
- `source_seal.rs`, `source_seal/`: read-only tracked source on Linux.
  `source_mtimes.rs`: unchanged files keep their times between jobs on Windows
  and macOS.
- `return_paths.rs`: returned files.
- `sibling_snapshots.rs`, `sibling_snapshots/`: read-only sibling checkouts.
- `caller_path.rs`, `caller_path/`: caller path checks and caller-root mapping.
- `retirement.rs`: retiring unused Git mirrors.
- `tenant.rs`, `tenant_agent/`, `tenant_local/`: running inside a tenant VM and
  answering `motor-host`.
- `windows.rs`, `windows/`: the Windows backend (`vm.rs` for QEMU, `hyperv.rs`
  for Hyper-V).
- `macos.rs`, `macos/`: the macOS backend.
- `boat_quota*.rs`: disk quotas in an overflow sandbox.
- `metrics.rs`, `metrics/`: monitor metrics for the dashboard.

## `crates/motor-module/src`

- `module.rs`: the daemon module: operations, caller admission, health.
- `motor.rs`, `motor/`: the client job engine: submit, follow, attach, cancel,
  health probes.
- `hosted.rs`, `hosted/`: the broker client and the TLS connection to hosts.
- `snapshot.rs`: snapshot capture.
- `transport.rs`: SSH to Windows and macOS runners.
- `storage.rs`, `storage/`: the job journal and checkpoints.
- `cli.rs`, `cli/`: `ck motor run`, `attach`, `cancel` and operator commands.
- `config.rs`: the module's configuration.

## `crates/motor-host/src`

- `server.rs`, `ingress.rs`, `relay.rs`: TLS admission and the relay to the
  tenant VM.
- `broker.rs`: heartbeats, usage reports and metrics to the broker.
- `billing.rs`, `store.rs`, `state.rs`: lease records, the SQLite store and
  in-memory admission state.
- `helper.rs`: requests to `motor-vm-helper`.
- `closure.rs`: closed customer accounts. `enroll.rs`: host keys and the
  facts the broker registers. `sandbox.rs`: the overflow sandbox's admission
  mode.

## Where to add new code

| Change | Place |
| --- | --- |
| Wire frames and codec shared by client and runner | `crates/motor-protocol`; regenerate the corpus with `crates/motor-protocol/tests/generate_vectors.py` |
| Caller-facing request and outcome types | The published `cortexkit-exec-remote-types` crate; `motor-protocol` re-exports them |
| Broker contract or token claims | Changed and published in the cloud service's own repository first; then re-pin `crates/motor-lease/contracts/cloud/` and update `crates/motor-lease` |
| Snapshot capture, transport, credentials, caller admission | `crates/motor-module` |
| Admission, queueing, transfers, workspaces, retention | `crates/motor-runner/src/engine.rs`, `server.rs`, `storage.rs`, `workspace/` |
| Linux job sandbox | `crates/motor-runner/src/isolation*`, `systemd.rs`, `network*.rs` |
| Hosted server admission, relay, broker reporting | `crates/motor-host` |
| Tenant VM lifecycle, disks, network | `crates/motor-vm-helper`, with provisioning in `script/tenant-provision/` |
| Tenant VM image contents | `script/tenant-image/` and the toolchain manifest `script/runner/toolchain.json` |
| Windows backend, host side | `crates/motor-runner/src/windows/` |
| Windows guest agent | `crates/motor-winagent` |
| macOS backend | `crates/motor-runner/src/macos/`, `crates/motor-macvm`, `crates/motor-macagent` |
| Compile cache and warm builds | `crates/motor-runner/src/compile_cache.rs`, `writer/`, `workspace/` |
| Repository gates and fences | `scripts/` |
| Documentation | `docs/`, one topic per file |

## Conventions

These are enforced by the checks in `scripts/`:

- Integration tests live as modules under the crate's `tests/it/`, not as new
  top-level test files.
- Test scratch directories come from `cortexkit_test_support::scratch_root()`.
- A test that needs a CortexKit daemon gets it from
  `cortexkit_test_support::SubcDaemonBinary`.
- A test that needs a privileged host is `#[ignore]` (runner) or behind a
  Cargo feature (VM crates), and fails rather than skips when a prerequisite
  is missing.
- Workspace crates have no build scripts (`scripts/no-build-scripts.py`);
  release builds pass the commit in `MOTOR_BUILD_COMMIT`.
- Nothing under `.cortexkit/` is committed (`scripts/check-cortexkit-layout.sh`).
